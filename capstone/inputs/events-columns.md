# Data Dictionary — `events.csv` (sensor readings)

*Draft 1. Describes every column in `inputs/events.csv`. All data is made up. The file is
generated by `scripts/make_events.py`; edit scenarios there, not in the CSV.*

## 1. How the file is organized

- **One row = one sensor's report on one track at one moment.**
- Each event has **7 time steps, 20 seconds apart** (2 minutes of readings).
- At each step every sensor has at least one row:
  - one row **per track it detects** (`Detection (Y/N)` = Y), or
  - a single row with `Detection (Y/N)` = N if it detects nothing, with the reason in
    `Sensor note`.
- **Blank cell = no data / not applicable.** A real "no" is written as **N**.
- **Simplification:** `Track ID` is already matched across sensors (T-1 from radar and T-1
  from RF are the same object). In a real system, matching reports to tracks is itself a
  hard step.

## 2. Conventions

| Item | Convention |
|---|---|
| Positions | Fort GBUS local grid from `site.md`, in **meters**. **x** = east (negative = west), **y** = north (positive = over the lake). Origin GRP-0 on the shoreline. |
| Directions | Degrees **true**, clockwise from north: 000 = north (over the lake), 090 = east, 180 = south (inland), 270 = west |
| Altitude | Meters above ground / lake level |
| Speed | Meters per second |
| Time | Local time (Eastern), `YYYY-MM-DD HH:MM:SS` |

## 3. Columns

### Identification

| Column | Meaning | Values / units |
|---|---|---|
| `Event ID` | Which of the eleven events | 01–11 |
| `Timestamp` | When the reading was taken | Local time |
| `Sensor ID` | Which sensor reported (positions in `site.md`) | S-RF, S-RAD, S-GIM, S-WAC, S-ACO |
| `Sensor Modality` | Sensor type, in words | RF, Radar, Camera, Wide Area Camera, Acoustic |
| `Track ID` | Which object this reading is about | T-1, T-2; blank if no detection |
| `Detection (Y/N)` | Did this sensor detect something at this moment? | Y / N |

### Position and motion

| Column | Meaning | Values / units |
|---|---|---|
| `X (m)`, `Y (m)` | Where the sensor places the target on the grid | Meters |
| `Altitude (m)` | Target height | Meters |
| `Position error (m)` | How far off this sensor's position can be. In each direction (east–west and north–south), about 95% of its readings fall within this distance of the true position. | Meters. RF 150, Radar 20, Camera 30, Wide Area Camera 100, Acoustic 60 |
| `Heading (deg)` | **Which way the drone is going** (see section 4 for where each sensor gets it) | Degrees true |
| `Speed (m/s)` | How fast the target is moving | m/s; 0 = hovering |
| `Bearing (deg)` | **Which way to look from this sensor** to see the target. Different sensors report different bearings for the same target. | Degrees true; radar and cameras only |
| `Elevation angle (deg)` | **How far above the horizon** the target is, seen from this sensor. The laser limit (ROE-5.7) uses the angle from the laser site. | Degrees; radar and cameras only |
| `Confidence (0-1)` | The sensor's own confidence in this reading | 0 (none) to 1 (certain) |

### What the target is

| Column | Meaning | Values | Filled by |
|---|---|---|---|
| `Radar size class` | Rough size from the radar return | Small, Medium | Radar |
| `Drone class` | Size group and type. RW = rotary-wing (multicopter); FW = fixed-wing. Groups follow the public DoD drone size groups. | e.g. Group 1 RW, Group 2 FW | RF, Camera, Acoustic |
| `Visual ID (Y/N)` | Camera has a usable image that shows what the object is | Y / N | Camera |
| `Camera channel` | Which camera channel produced the reading | Visible, IR, High-speed | Camera |
| `Blade spin seen` | High-speed or visible image shows spinning rotors (rules out birds) | Y / N | Camera |
| `Payload seen` | Something carried by the drone is visible | Y / N / Unknown | Camera |

### Control link and pilot (RF only)

| Column | Meaning | Values |
|---|---|---|
| `Control link present` | A live radio link between drone and controller is detected. **Required for the jammer (ROE-5.1).** | Y / N |
| `Protocol family` | Generic, made-up name for the type of link | e.g. Hobby-A, Unknown-B (encrypted), Blue-Mil (authorized) |
| `Remote ID` | The drone's broadcast identity, if any | ID and "(broadcasting)", or "None detected" |
| `Pilot located (Y/N)` | RF network has estimated the pilot's (controller's) position | Y / N |
| `Pilot X (m)`, `Pilot Y (m)` | Estimated pilot position | Meters |
| `Pilot position error (m)` | Accuracy of the pilot estimate (larger for distant pilots) | Meters |

### Notes

| Column | Meaning |
|---|---|
| `Sensor note` | Free text: why there was no detection (fog, out of range, not yet cued), what was cued by what, degraded status, clutter, what the camera saw |

## 4. Where each sensor's values come from

Different sensors measure different things. The same column can mean slightly different
things depending on the sensor. **Differences between sensors are information, not
errors.**

| Sensor | Position | Altitude, heading, speed | Bearing / elevation | Identifies? |
|---|---|---|---|---|
| **RF (S-RF)** | Estimate from the three-node RF network | **From the drone's own telemetry** (decoded from its signal): what the drone *reports about itself* | — | Yes: protocol, Remote ID, control link, pilot position |
| **Radar (S-RAD)** | Measured: bearing + range | Calculated from the track over time | Measured | No (size only) |
| **Camera (S-GIM)** | From bearing + range supplied by the cueing sensor | Calculated from the track | Measured | Yes: visual ID, blade spin, payload |
| **Wide Area Camera (S-WAC)** | Rough, from bearing and estimated range | Calculated from the track | Measured | No (detects only) |
| **Acoustic (S-ACO)** | Estimated from arrival times across the array | Calculated from the track | — | Partly: rotary vs. fixed-wing |

**Why the heading source matters:**
- RF heading is what the drone **thinks** it is doing (nose direction from its own
  navigation). Radar and camera heading is what it is **actually** doing over the ground.
- They can differ, for example in a strong crosswind off the lake.
- A large unexplained difference could mean the drone's telemetry is **false (spoofed)**,
  which is itself a threat indicator.

## 5. Related files

| File | What it adds |
|---|---|
| `site.md` | Grid, zones, sensor and defeat-option positions |
| `health-status.json` | Which sensors are degraded or down at each time (e.g., acoustic degraded in event 07) |
